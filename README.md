# БурмалСТРОЙ (Приложение «ОБЩАГА»)
Веб-система для подачи и обработки заявок на ремонт в общежитии. 
Данная версия является **MVP (Первым показом)** и реализует строго те требования, которые были согласованы в паспорте проекта и ТЗ.

## 🎯 Что реализовано (Первый показ)
- **Студент**: подача заявки (ФИО, дата подачи, комната, описание) и просмотр статуса своих заявок.
- **Специалист**: просмотр всех заявок и смена статуса (Новая / В работе / Выполнена).
- **Заведующий**: просмотр сводки за выбранный период (по умолчанию — за последнюю неделю) с визуализацией по статусам.
- **Журнал изменений**: фиксация каждого изменения статуса (кто, когда, старый и новый статус).
- **Безопасность**: ролевая модель (менять статус может только «специалист»), клиентская и серверная валидация.
- **Обработка ошибок**: понятные сообщения для пользователя, запись критических ошибок в `error.log`.
- **Резервное копирование**: скрипт для сохранения копии БД.

## 🚫 Что НЕ входит в эту версию (Следующая поставка)
- Система уведомлений (Email, Push, SMS, внутренние).
- Отправка подтверждений о получении заявки.
- Фильтры для уточнения сводки.
- Экспорт сводки в CSV/PDF.
- Экран администратора и управление пользователями.

## 🚀 Быстрый старт

### Требования
- Node.js (версия 18 или выше)
- npm

### Установка и запуск
Перейдите в папку с бэкендом:
```bash
cd backend
```

Создайте файл настроек (скопируйте `.env.example` в `.env`):
```bash
cp .env.example .env
```
*(Для Windows используйте команду `copy .env.example .env`)*

Установите зависимости и запустите сервер:
```bash
npm install
npm start
```

Приложение будет доступно по адресу: **http://localhost:3000**

## 👥 Тестовые аккаунты
Вы можете зарегистрировать новых пользователей через форму на сайте. 
Для быстрой проверки используйте следующие данные (пароль: `123`):

| Роль | Логин | Что может делать |
|---|---|---|
| Студент | `student` | Создавать заявки, видеть только свои заявки |
| Специалист | `spec` | Видеть все заявки, менять статус, смотреть журнал |
| Заведующий | `manager` | Выбирать период и смотреть сводку по статусам |

## 💾 Резервное копирование БД
Перед демонстрацией проекта (согласно реестру рисков) необходимо сделать резервную копию базы данных.
Находясь в папке `backend`, выполните:
```bash
npm run backup
```
Копия базы данных будет сохранена в папку `backend/backups/`.

## 🛠 Технологии
- **Backend**: Node.js, Express, better-sqlite3 (SQLite), JWT (авторизация), bcryptjs.
- **Frontend**: Vanilla HTML5, CSS3, JavaScript (без сторонних фреймворков).
- **БД**: SQLite (файл создается автоматически в `backend/data/burmalstroy.db`).

## 📋 API (Краткая справка)
| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/api/auth/register` | Все | Регистрация пользователя |
| POST | `/api/auth/login` | Все | Вход (получение JWT) |
| POST | `/api/requests` | Студент | Создать заявку |
| GET | `/api/requests` | Авторизованные | Список заявок (студент — свои, персонал — все) |
| PATCH | `/api/requests/:id/status` | Специалист | Сменить статус заявки |
| GET | `/api/requests/:id/history` | Авторизованные | Получить журнал изменений заявки |
| GET | `/api/reports/summary` | Заведующий | Получить сводку за период (`?from=YYYY-MM-DD&to=YYYY-MM-DD`) |

## 🧪 Сценарии для приёмки (3 сценария)
1. **Пустые поля**: При отправке пустой формы заявки срабатывает клиентская валидация (сообщение «Заполните все поля!»), сервер также отклоняет запрос с кодом 400.
2. **Отказ доступа**: Студент или заведующий при попытке отправить запрос на смену статуса получают ошибку 403 `{"error": "Отказано в доступе: недостаточно прав"}`.
3. **Сводка без данных**: Если у заведующего выбран период, в который не было заявок, выводится сообщение «За выбранный период заявок нет», система не падает.
